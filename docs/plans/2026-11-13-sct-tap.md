# SCT Homebrew Tap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Track execution with the session todo tool, not this file.

**Goal:** Deliver conventional formulae, local/upstream casks and reviewed dual-architecture bottle automation for the SCT tap.

**Architecture:** Use standard Homebrew package definitions and build/publish commands. Keep static graphics variants separate from official packages. Use a local-artifact Aseprite cask and never publish that application's binaries.

**Tech Stack:** Homebrew Ruby DSL, C/C++, CMake, pkgconf, GitHub Actions, shell, Ruby Minitest for CI selection/security logic.

**Spec:** `docs/specs/2026-11-13-sct-tap-design.md`

## Global Constraints

- Tap identity: `0xsct/tap`; GitHub repository: `0xSCT/homebrew-tap`.
- Native architectures: `arm64` on macOS `27+`; `x86_64` on macOS `26+`.
- Preserve pyenv Python `3.14.3`; never edit pyenv configuration or use an undeclared host interpreter in formula builds.
- Formulae under `Formula/`; globally distinct casks under `Casks/`.
- Keep existing ImGui archives, headers and all three pkg-config module names.
- Static-only graphics libraries retain upstream native capabilities; macOS system dependencies remain dynamic.
- Keep normal upstream LLVM/LLDB features and qualify LLDB's custom LLVM dependency. Build their tap bottles only on Intel; ARM users use official LLVM/LLDB.
- No Aseprite binary publishing or CI build/download/installation jobs. Its cask installs the user's local built archive.
- Remote artifacts require verified SHA-256 values. No quarantine removal or Gatekeeper bypass.
- GitHub builds run automatically. Publication is manually approved and bound to the reviewed PR SHA.
- Preserve existing untracked `.gitignore`, `README.md` and `Formula/` content while integrating requested changes. Do not stash or discard it.
- Do not delete anything outside the workspace. Host verification must not uninstall or replace unrelated packages.
- Do not stage, commit or push repository changes in this session. The user owns all commits and pushes; verification fixtures are isolated from repository history.
- Do not claim native Intel builds, app launch, publication or heavy LLVM builds succeeded without observing them.

## Review Focus

1. Multi-commit pushes and initial pushes: every added/changed formula is selected, not only the final commit's changes.
2. Stale, rerun or failed PR builds: publication must reject mismatched heads, unsuccessful current native run attempts, missing per-formula bottles and incompatible branch policy.
3. Static consumers: linking metadata must resolve all requested graphics archives without selecting neighboring dylibs.
4. Shared GStreamer installation: uninstall metadata must not remove the complementary SDK or user-owned unrelated files.
5. Local Aseprite input: readall must work before the user builds the app; local file selection must match version and native architecture without remote fallback.

### Task 6: Native builds and reviewed bottle publication

**Review:** per-task — security and concurrency

**Files:** Create `.github/workflows/tests.yml`, `.github/workflows/publish.yml`, `.github/scripts/tap_ci.rb`, `.github/scripts/tap_ci_test.rb`, `.github/dependabot.yml`, `.rubocop.yml`.

**Interfaces:**
- `TapCI.changed_formulae(base_sha:, head_sha:, repository:) -> Array<String>` selects complete pushed-range changes; zero base selects all current formulae. Only existing supported formula paths yield names.
- `TapCI.verify_publication!(pull_request:, expected_sha:, selected_run:, expected_bottles:, downloaded_bottles:, branch:) -> nil` raises on a mismatched head, stale/failed run attempt, unsuccessful required native jobs, protected/unknown branch policy or an invalid expected bottle set. `selected_run` carries the exact Homebrew-selected `tests.yml` run ID, attempt and native job results; `expected_bottles` maps qualified formula names to reviewed Homebrew package versions and required tags: graphics use `arm64_golden_gate`/`tahoe`, while `llvm-sct`/`lldb-sct` use only `tahoe`; `downloaded_bottles` supplies actual retained JSON entries, archive paths and computed SHA-256 values. Compiler-only changes require no ARM bottle artifact. Validate every top-level JSON record and require nonempty structured tag maps before flattening; hidden records never reach upload.
- Script command `changed-formulae BASE HEAD [ARCH]` prints comma-separated short formula names. `build-native ARCH FORMULAE` schedules canonical tap dependency identities but executes standard Homebrew commands. `verify-native ARCH FORMULAE` requires the complete selected native archive/JSON set before job success.
- Publication validation uses structured GitHub API data; PR numbers/SHA values are passed as validated data, never executable shell interpolation.
- Native artifacts use `bottles_arm64_<run-id>_<attempt>` and `bottles_x86_64_<run-id>_<attempt>`. Required runner identities are `xcode-27` and `macos-26-intel`. The run/attempt-specific glob is passed to `pr-pull --artifact-pattern`; do not accept generic artifacts from a different run or attempt.
- `TapCI.native_formulae(names:, formulae:) -> Array<String>` topologically orders short selected names using structured canonical Homebrew dependency metadata. `TapCI.native_commands(formula) -> Array<Array<String>>` provides the pure supported CLI plan. The executor requires `GITHUB_ACTIONS=true`, exact case-insensitive repository identity and matching native architecture before uninstall/build; only ephemeral CI jobs clean selected roots.
- `TapCI.verify_native_bottles!(expected_bottles:, architecture:, directory:) -> nil` shares publication's strict pair validation for that native platform, including identity/version/path/root URL/basename/hash checks and rejection of unreviewed core records.

- [ ] Add isolated Minitest cases for multiple changed commits, added/deleted formulae, cask-only changes and all-zero initial base. Use disposable Git fixtures within the workspace; assert selected package names.
- [ ] Add Minitest cases proving publication rejects changed PR SHA; newer failed runs at the same SHA; reruns with a different attempt; failed/incomplete/missing required native jobs; a missing formula bottle despite architecture artifacts existing; version/tag/archive-hash mismatches; and protected/unknown branch policy. Assert specific rejection errors. Compiler-only changes accept an Intel-only bottle set; mixed changes still require both graphics platforms. Cask-only/deleted-only expected sets remain empty.
- [ ] Base workflows on current Homebrew templates and pinned action SHAs. Replace runner matrix with `xcode-27` and `macos-26-intel`; assert actual native architecture and OS at job start.
- [ ] Run syntax/style/audit in read-only jobs. Filter selected packages per native platform: graphics on both, `llvm-sct`/`lldb-sct` only on Intel. Schedule selected tap prerequisites first using canonical native Formula dependency identities, while retaining short archive names. In the guarded ephemeral runner, remove a preinstalled selected root before `brew install --only-dependencies --include-test --build-from-source` so the actual missing closure can bootstrap outside bottle mode. Then install the selected root with `--build-bottle --include-test`, run `brew test`, and run `brew bottle --json` with the reviewed versioned release root URL. Never combine source/bottle flags or use unsupported `reinstall --build-bottle`.
- [ ] Preserve genuine eligible affected-dependent tests through a separate `test-bot --only-formulae-dependents` phase with short testing/tested names. Remove inappropriate native Tier-1 setup/cleanup gates. Require every selected native archive/JSON pair before job success, and upload only reviewed tap bottles under the existing exact run/attempt artifact names; core dependencies are not bottled or published.
- [ ] Add behavior regressions for all three initial tap dependency pairs, the unbottled Intel dependency bootstrap command path, preinstalled-root build-dependency pruning, missing expected native pairs, execution environment guards and exact mixed-case GitHub identities. Preserve protected-main, hidden-record and prior trust-boundary coverage.
- [ ] Do not add Aseprite-specific CI build, fetch or installation steps. Generic Ruby syntax checks may parse its definition. Remote cask checks validate real downloads; do not confuse cask installation with source compilation.
- [ ] Add manual publisher inputs for PR number and required reviewed head SHA. Reuse Homebrew's newest `tests.yml` check-suite selection, bind run ID/attempt and require its successful native jobs. Derive expected formula names/package versions from the reviewed checkout. Run `brew pr-pull --no-upload --retain-bottle-dir --head-sha` with that exact run/attempt's artifact pattern; recheck current run attempt/head and validate every retained tarball/JSON pair before `brew pr-upload` uploads those same files.
